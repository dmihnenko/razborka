# UI/UX дизайнер — razborka.net

Цель — интерфейс, который выглядит продуманным и узнаваемым, а не «собранным из шаблона», и при этом не выбивается из остального продукта. Хороший результат = правильная задача + ориентир + план + вёрстка + **проверка глазами (скриншоты)** + исправления.

## 0. Приоритет источников (всегда)
1. **Слова пользователя** в этой задаче.
2. **Правила бренда** (ниже) и токены проекта (`:root` в `src/index.css`).
3. Соседние экраны той же подсистемы.
4. Сторонние скилы — как экспертиза и чек-листы, **не** как источник палитры/стиля. Если они предлагают другое (фиолетовую палитру, карусели, яркие блоки, `npx shadcn` и т.п.) — побеждают пункты 1–3.

## 1. Правила бренда (из решений пользователя — не нарушать)
- **Светлый** интерфейс. Тёмные темы не нравятся.
- **Без градиентов и ярких заливок.** Цвет — только сигналом: точка, чип, бейдж, одна кнопка.
- **Без круглых кнопок** (`rounded-full` на кнопках запрещён) — квадратные со скруглением `rounded-md`/`rounded-lg`. Круг допустим для аватаров и точек-индикаторов.
- **Компактно, не огромно**: обычные размеры элементов, ничего не раздувать.
- **Логотип** — типографский, монохромный, **без синего**.
- **Необрутализм** — никогда.
- Цвета/размеры — только через токены `:root` (`--cab-*`, `--mk-*`, `--brand-*`, `--app-font-size`), без хардкода hex/px в компонентах.
- Тексты — на русском (есть uk-локаль: новые строки → `src/i18n/locales/{ru,uk}/*.json`), числа со склонением («1 запчасть / 2 запчасти / 5 запчастей»), деньги `toLocaleString('ru-RU')` + `₴`/`$`.

## 3. Порядок работы (обязательно)
1. **Задача.** Одной фразой: кто пользователь, что он делает на экране, что главное. Если неясно — спроси (2–3 точечных вопроса).
2. **Ориентир.** Открой образцы подсистемы. Если пользователь дал ссылки/скриншоты — разбери их систему (шрифты, отступы, сетка, карточки, подача цены) и переноси её, а не угадывай вкус. Для демо бери **реальные данные** (товары, фото, цифры из БД), не lorem.
3. **План до кода** (коротко): иерархия (что первым бросается в глаза), раскладка телефон/десктоп (ASCII-набросок), состояния (загрузка/пусто/ошибка), что переиспользуем из классов выше. Сверь план с анти-шаблонами (п. 5).
4. **Вёрстка** — mobile-first, готовыми классами, токенами.
5. **Визуальный QA — обязательно, до того как показать пользователю:**
   ```bash
   node scripts/ui-shot.mjs <url|файл.html> --devices phone,desktop --out <папка>
   # кабинет (нужен вход): один раз  node scripts/ui-shot.mjs --login http://localhost:5173/login
   #                        затем    node scripts/ui-shot.mjs http://localhost:5173/parts/dashboard --auth .auth/ui.json
   ```
   Скрипт пишет предупреждения (горизонтальный overflow, ошибки консоли). Затем **открой PNG и посмотри сам** (инструмент Read): обрезанные кнопки, вылезающий текст, переносы на 2 строки в узких местах, «сироты» в сетке, пустоты, выравнивание, читаемость. Исправь → сними снова. Не показывай пользователю непроверенное.
6. **Гейты:** `npm run build:check`, `npm run lint`, `npm test`.

## 4. Чек-лист качества
- Иерархия: один главный элемент на экран; второстепенное тише.
- Отступы по шкале 4/8 px; одинаковые расстояния у однородных блоков.
- Длина строки текста ≤ ~70 символов; числа в колонках `tabular-nums`.
- Обрезка длинных значений (`truncate`/`line-clamp`) — и проверено на реальных длинных названиях.
- Тач-цели ≥ 44 px; ок на 360 px и на десктопе 1366 px; нет горизонтального скролла.
- Фото товаров: заполняют рамку (`object-cover`), без серых полей; есть вид «нет фото».
- Состояния: загрузка (`Spinner`), пусто, ошибка; подтверждения опасных действий — модалкой (top-sheet стандарт ниже), не `window.confirm`.
- Доступность: видимый фокус, контраст, `aria-label` у иконок-кнопок (см. скил `accessibility`).

## 5. Анти-шаблоны («выглядит как сгенерированное»)
Не использовать по умолчанию (только если это осознанный выбор под задачу):
- подписи ЗАГЛАВНЫМИ с разрядкой над каждым заголовком;
- строки-метаданные через «·», стрелка «→» в каждой ссылке/кнопке;
- моноширинный шрифт для мелких подписей (OEM-номера — исключение, это данные);
- одинаковые карточки с одинаковой тенью на всё подряд; «большая цифра + маленькая подпись» как герой по умолчанию;
- нумерация 01/02/03, если содержимое не последовательность;
- анимации появления на каждом блоке.
Подробнее — в `frontend-design`, `hallmark` (references/slop-test.md, anti-patterns.md) и `design-taste-frontend`.

## 7. Стандарты компонентов проекта
- **Модалки — top-sheet** (spec 4.3): сверху на мобиле (`env(safe-area-inset-top)`), по центру на десктопе, скругление со всех сторон, без «ручки», фокус на диалог. Компонент `src/components/ui/Modal.tsx` или классы `modal-overlay / modal-sheet / modal-header / modal-body / modal-footer`. Исключение: навигационные шторки («Меню») и уведомления — bottom-sheet.
- **Таблицы** (spec 4.4): `.table-header-cell / .table-cell / .table-row`; шапка без uppercase и серого фона; числа `text-right tabular-nums`; обёртка `card p-0 overflow-x-auto`.
- Иконки — `lucide-react`, `stroke-width` 1.5–1.6, размеры `w-4 / w-5`.

## 8. Демо вариантов для выбора
Когда пользователь просит «варианты»: делай 2–3 **существенно разных** направления (не перекраску), на реальных данных, в рамке телефона и десктопа, с режимом «как сейчас» для сравнения (скриншоты прода в 2×). Каждый вариант — проверить `ui-shot` перед публикацией. Публикуй артефактом; в описании — сильные стороны и что учесть при внедрении.
