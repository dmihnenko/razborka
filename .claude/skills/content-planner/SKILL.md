# Контент-планировщик razborka.net

Превращает реальные возможности продукта, ассортимент и поисковый спрос в план публикаций (RU + UA). Блога на сайте пока нет: статья как формат — это сначала решение владельца и отдельная задача, а не само собой разумеющийся пункт плана.

## Источники тем (только реальные)

1. `git log` — что реально выкатили (`git log --since="30 days ago" --oneline`; бери `feat(...)`, пропускай `fix`, `docs`, `chore`, `style`).
2. `docs/` — планы и аудиты (то, что только в планах, наружу как готовое не выносить).
3. Существующие публичные страницы: маршруты в `src/App.tsx`, серверное SEO и sitemap в `worker/index.js`.
4. Ассортимент: какие марки, модели и разборки реально есть на маркете.
5. Данные запросов — от `keyword-researcher`; Search Console, если доступна. Частоты не выдумывать.

## Кластеры по намерению

| Намерение | Пример | Целевая страница | CTA |
|-----------|--------|------------------|-----|
| Покупка детали | запчасти на конкретную модель | каталог марки/модели, товар | заявка на товар |
| Выбор разборки | разборки в городе | `/market/suppliers`, страница разборки | перейти к товарам |
| Подключение разборки | учёт для авторазборки | `/business` | заявка `/business/apply` |
| Информационное | как проверить деталь по номеру OEM | статья, если решено её вести | мягкий: ссылка в каталог |

Кластер = опорная страница + страницы-спутники, ссылающиеся на неё и друг на друга.

## Ритм

- Качество важнее частоты; каждая публикация сразу в RU и UA.
- Раз в квартал: обновить 2–3 старые страницы — часто полезнее новой.

## Процесс

1. Собери сырьё: git log, docs, список текущих страниц, ассортимент.
2. Отфильтруй: что важно пользователю и реально работает на проде.
3. Сопоставь с запросами (`keyword-researcher`): у каждой темы свой основной запрос; нет каннибализации. Если тема уже закрыта — обновление, а не новая страница.
4. Расставь по кластерам и приоритету: сначала коммерческие, затем информационные.
5. Заполни карточку темы.
6. Пропиши перелинковку (`internal-linking-optimizer`).
7. Передай темы `seo-copywriter`; после выхода — `on-page-seo-auditor`.

### Карточка темы

```
Тема / рабочий заголовок:
Основной запрос (RU / UA):
Намерение: покупка | выбор | подключение | инфо
Источник в продукте: функция, коммит, данные маркета
Опорная страница и внутренние ссылки:
Формат: страница | статья
Дата выхода (RU+UA):
Метрика успеха: показы/клики в GSC по запросу, переходы на целевое действие
```

## Чек-лист

- [ ] Темы взяты из git log, docs, ассортимента и существующих страниц, а не придуманы
- [ ] Нет тем, обещающих несуществующие функции
- [ ] У каждой темы свой запрос, нет каннибализации
- [ ] Кластеры: опорная страница + спутники, намерение указано
- [ ] Для каждой темы запланированы RU и UA версии
- [ ] Перелинковка прописана
- [ ] Частота реалистична, есть слот на обновление старых страниц
- [ ] Метрика успеха и дата ревью плана заданы
- [ ] После публикации выполнено SEO-правило из корневого `CLAUDE.md`
