# Подбор запросов (razborka.net)

Строит семантическое ядро для публичных страниц и привязывает каждый запрос к одной странице. Рынок: Украина, языки RU и UA. Две аудитории: покупатель запчасти (маркет) и владелец авторазборки (CRM и размещение).

## Честность данных

- Частоты, конкуренцию и позиции **не придумывать** и не «вспоминать по памяти».
- Каждое число маркируется: `факт (источник, дата)`, `оценка` (качественно: высокая/средняя/низкая, без цифр) или `не проверено`.
- Нет данных — в отчёте явно: «частоты не проверены; проверить в Google Search Console (Эффективность → Запросы) и Google Keyword Planner, регион Украина, языки RU/UK».
- Сначала используй собственные данные: GSC показывает реальные запросы и показы сайта.

## Сидовые темы (из реального продукта)

| Тема | Страница-кандидат |
|------|-------------------|
| Б/у запчасти, авторазборка, запчасти с разборки | `/market`, `/market/catalog` |
| Запчасти на марку и модель | `/market/catalog/<марка>`, `/market/catalog/<марка>/<модель>` |
| Запрос по номеру OEM или названию детали | страница товара `/market/part/:id`, каталог |
| Конкретная разборка, разборки в городе | `/market/suppliers`, `/market/supplier/:id` |
| CRM и учёт для авторазборки, программа для разборки | `/business`, `/business/apply` |

Точные маршруты сверяй с `src/App.tsx`, серверные мета-теги и sitemap — с `worker/index.js`. Ассортимент определяет, что можно продвигать: марки и модели бери из `market_inventory` / `get_market_car_catalog`, а не из головы.

## Процесс

1. **Сиды.** Тема и 5–10 базовых фраз покупателя («амортизатор model y б/у») или владельца разборки («как вести учёт запчастей на разборке»).
2. **Расширение.** Модификаторы: б/у / разборка / купить / цена / оригинал; марка, модель, год; город; номер OEM; вопросы («как», «что такое», «чем отличается»). Подсказки поиска, «Похожие запросы», People Also Ask — только через реальный просмотр, не по памяти.
3. **RU и UA отдельно.** Украинские запросы собирай самостоятельно («запчастини б/в», «авторозбірка», «розбірка Tesla», «облік запчастин»). Не переводи RU-список автоматически.
4. **Намерение.** Для каждого запроса: информационное / сравнение / коммерческое / навигационное. Нерелевантные — в минус-лист.
5. **Кластеризация.** Запросы, на которые Google отвечает одной страницей, — один кластер. Проверка: по двум запросам открой выдачу; те же страницы — один кластер.
6. **Сопоставление «запрос → страница».** Один кластер = одна страница; у страницы 1 основной + 3–8 вторичных запросов. Две страницы на один кластер — каннибализация: объедини или раздели намерения.
7. **Приоритет.** Есть товар или функция → намерение (коммерческое выше) → конкуренция (оценка) → пробел на сайте. Частоты — только при наличии данных.
8. **Передача.** `seo-copywriter` (текст), `content-planner` (даты), `meta-tags-optimizer` (title/description).

## Формат результата

```
| Кластер | Основной RU | Основной UA | Вторичные | Намерение | Страница | Статус | Частота | Примечание |
```

## Минус-слова и ловушки

- Запросы на марки и модели, которых нет в наличии, — не приоритет: страница будет пустой.
- Новые оригинальные запчасти и официальные дилеры — не основной спрос маркета б/у.
- Ремонт авто, услуги СТО — не наша аудитория (СТО из продукта удалён).
- Запросы на функции, которых нет в проде, — не брать.

## Отчёт

Коротко: таблица кластеров, «пробелы» (запрос есть, страницы нет), конфликты (каннибализация), список данных, которые нужно достать из GSC / Keyword Planner. Без обещаний позиций и трафика.

## Чек-лист

- [ ] Сиды взяты из реального ассортимента и функций продукта
- [ ] RU и UA ядра собраны отдельно, UA не калька
- [ ] У каждого запроса указано намерение; минус-лист составлен
- [ ] Кластеры проверены по выдаче, а не на глаз
- [ ] Один кластер = одна страница; каннибализации нет
- [ ] Все числа помечены `факт` / `оценка` / `не проверено`; ничего не выдумано
- [ ] Указано, что проверить в Google Search Console и Keyword Planner
- [ ] Результат передан в seo-copywriter / content-planner / meta-tags-optimizer
